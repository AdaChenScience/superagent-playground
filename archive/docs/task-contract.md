# 下一轮任务：只交付值得关注的变化

[返回首页](../README.md) · [运行说明](runbook.md)

这是根据使用者反馈修订的下一轮规范，尚未派发或验证；不是历史运行规则。先手动跑一次增量，不直接建立定时任务。

## 输入和目标

输入上一期 `docs/pilot-001/tracking.json`、旧证据、明确的 UTC 截点和 Marin 主训练入口。上期截止为 2026-11-02 05:30 UTC。旧快照可能有不严谨表述，必要时回读来源并列为纠正，不能当作绝对真值。

回答：相比上次有哪些值得我花时间理解的变化？它改变了数据、模型、训练运行、评测或阶段成果中的哪一环？与制作视频有什么关系？主线入口要扩展到新增关联讨论，不能只查旧链接，也不能把 `updated_at` 变化当成实质进展。

## 交付

一页更新简报，最多三项重要变化；没有就明确写无。每项只保留：之前怎样、现在变了什么、为何值得关注、一句背景解释、关键来源、下一次什么证据会改变判断。结论区分计划、实现、测试、合并、主训练采用和能力结果。

另附短表，列出已检查但不收录的变化及理由；保存更新后的跟踪快照和证据。不要默认生成口播稿、分镜或长篇教学材料。选题成立后再展开。

## Agent 如何工作

由主执行 Agent 决定研究拆分；核查者独立回读重要来源，编辑者按 Humanizer-zh 规范压缩表达。主执行 Agent 整合并检查事实、重复项和变化前后是否可比。子 Agent 数量不作为验收条件，不要求为了展示而扩充角色。

普通查证、修稿与提交自行处理。只有研究范围取舍、需要用户选择的选题方向，或新增权限、费用、对外发言时才返回具体选项。未知事实标未知，不让用户裁决真假。

## 怎样判断这轮有没有用

- 每个“新进展”都能指出相对旧快照的新证据；旧结论纠正单列。
- 不收录的工程变化有理由，避免用“重要性排序”掩盖未检查。
- 使用者读完简报，能说明发生了什么、为什么重要，并决定是否深入；由实际阅读确认，不用字数或模型自评替代。
- 记录使用者实际点开的来源、追加解释和返工；作为以后比较的基线，本轮不预设节省比例。

只读 Marin，只向成果仓库交付新的 PR；引用旧任务和快照，不向已合并 PR #4 继续提交。不跑训练、不下载权重、不向上游发言、不自动发布视频。权限范围靠部署和账号设置配合，提示词不等于安全隔离。
