# 选题简报：Marin 535B-A23B 试刊 001

## 观察窗口与范围

观察窗口是 2026-10-19T05:30Z 至 2026-11-02T05:30Z（UTC，14 天）。只读公开的 GitHub 记录；训练曲线、内部事故页、模型权重和训练日志没有读，一个第三方看板只当线索。下面三个选题按推荐顺序排列。本轮无需决策。

## 1. Marin 开始练习读更长的文本：切换成功，离能力证明还有多远？（推荐）

**发生了什么**：11 月 2 日凌晨，Marin 把一条已经跑了 95% 的 535B 模型训练，从“一次能读约 1.6 万个 token”切到“约 6.5 万个 token”。token 是模型把文本切分后处理的小片段，不固定等于一个字或一个词；上下文是一次能处理的文本长度。切换发生在总步数的 95.3%，剩下 4.7% 的路程；代码合并后启动新阶段，六项切换后检查（放行条件）在 103 步内通过。此前团队先在一个机架（一组机器）上排练了两次。

**为什么值得讲**：这是训练尾段的一次真实取舍：为什么不在开头就用长上下文、为什么最后才切、切换后要检查什么。它也能讲清“切换成功”和“模型变强”不是一回事。

**适合讲的角度**：镜头对准“决策和检查”，不是“能力发布”。讲三件事：为什么把长上下文放在最后、为什么选更稳的并行方式、六项切换后检查各自防什么。

**证据与限制**：切换后检查由团队/代理报告，没有独立复核；只覆盖切换后的 103 步；截点前还没有新上下文下的评测结果；几个评测改进还没合并；评测时把文本拼多长也会影响分数。原始记录见 [Marin 的切换记录](https://github.com/marin-community/marin/issues/10821)。

## 2. 分数变了，先问尺子：评测口径与长上下文的隐藏陷阱

**发生了什么**：同一批差不多的模型权重，只改变评测时“把文本拼多长”，Paloma 评测集的总分就差了约 0.03。Paloma 是一组验证文本，总分是各子集分数的平均。到约 26 万 token 的上下文时，两个较短的验证集不够一条序列，会被静默跳过，总分变成其余 14 个子集的平均，可能让告警误报。

**为什么值得讲**：教“分数变了，先查尺子有没有变”的测量素养；这也解释了为什么团队不敢直接相信切换后的第一个分数。

**适合讲的角度**：同一批权重、两种拼接长度；短数据为什么会消失；修复为什么还没合并。

**证据与限制**：0.03 是一位外部观察者的一次测量，不是 Marin 官方评测，也没有复现；26 万 token 的阶段还没开始；修复已获批准，但还没合并、没在显卡上排练；用更短的 4 千 token 口径重评是跑完后的承诺，截点前没有公开记录。原始记录见 [打包测量](https://github.com/marin-community/marin/issues/8435#issuecomment-6336070902) 与 [评测修复](https://github.com/marin-community/marin/pull/10711)。

## 3. 一次没有响的保险丝：梯度尖峰与梯度裁剪

**发生了什么**：训练中出现过几次“梯度”突然变大。梯度是模型每次更新的方向和幅度，太大会让训练抖动；最大的一次约为平时中位数的 41 倍。团队精确复现了其中一次，追到一条长文本里的一个位置和一处计算，并给主训练加了“梯度裁剪”（把每次更新的幅度限制住）。上线后到某个检查点为止，这个限制一次都没有触发。

**为什么值得讲**：一个从现象追到极细微数值的调试故事；也适合讲“装了保险丝”和“保险丝真的救过场”不是一回事。

**适合讲的角度**：尖峰—定位—修复—主训练观察；最后落在“单机架恢复测试里触发过，但主训练观察里还没触发，所以效果仍未验证”。

**证据与限制**：只有一次尖峰的机制被精确复现，另外两次没有复现；裁剪只在单机架恢复测试里触发过，进入主训练后到某个检查点为止没有触发；它与 10 月 29 日的集群显存回收故障是不同问题，没有证据表明两者有关联。原始记录见 [梯度调查](https://github.com/marin-community/marin/issues/10677) 与 [裁剪改动](https://github.com/marin-community/marin/pull/10783)。

## 推荐与理由

选第 1 个。它有明确时间点、可核对数字、完整的“决策—排练—合并—检查”链条；限制条件本身就能教人：切换通过不等于能力提升。第 2 个概念更普适，但 5–8 分钟容易讲成方法论；第 3 个故事性强，但“保险丝”还没在主训练里触发，结论容易讲虚。
