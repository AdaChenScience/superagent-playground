# 教学稿：Marin 开始练习读更长的文本：切换成功，离能力证明还有多远？

## 开场（约 30 秒）

2026 年 11 月 2 日凌晨（UTC），Marin 535B-A23B 这条模型（由许多专家分工处理，MoE）把训练时一次能读的文本长度从 16K 提到 65K。切换发生在第 372,000 步，离总步数 390,251 只剩 4.7%。这是一次带切换后检查的工程切换，不是能力发布。

## 问题：为什么要把上下文拉长，而且放在最后

训练语言模型，就是让模型不断猜下一个 token。token 是模型把文本切分后处理的小片段，不固定等于一个字或一个词。上下文是一次能处理的文本长度。K 在这里指 token 数：4K 约 4 千，16K 约 1.6 万，65K 约 6.5 万，262K 约 26 万。

上下文越长，模型能利用的前文越多；代价是注意力（模型在序列里决定看哪些位置）要处理更多两两关系，显存和跨卡通信都会涨。所以常见做法是先短后长：大部分步数用短上下文跑完，最后一段再拉长。短上下文便宜、能多跑；长上下文只在尾段跑，让模型适应更长的输入。这条主线在 10-14 已经从 4K 切到 16K，那是窗口外的背景；现在把 65K 放在最后 4.7%，262K 阶段排在后面。

这里用一个填空句做教学比喻（类比），不是真实实验：

“今天下雨，出门要带___。”

如果前面再加一句“昨天预报就说今天有雨，早上天一直很阴”，空格处填“伞”的可能性会更高。前文越多，答案越可预测。模型的上下文变长，作用类似：能参考的前文更多。

但在真实评测里，改变打包长度本身也可能让分数移动。打包是把多条短文本拼进一个定长序列，减少补齐长度（padding）的浪费；打包长度会改变评测时看到的序列边界。10-22 有独立观察者在几乎相同的权重上测到，16K 打包的 Paloma 评测集总分（各子集分数的平均）比 4K 低约 0.031；这是单个训练存档、单次测量，不是 Marin 官方评测，也没有复现。它说明“上下文变长”和“分数变高”不能直接画等号。

训练中途会存训练存档（checkpoint），通常包含模型参数和恢复训练所需的状态，不只是权重。这次切换就是从第 372,000 步的训练存档长出一个新子训练（从该存档接着跑的新进程）。存档能保存不等于能顺利恢复；两次单机架排练只验证了保存，没有验证恢复，所以切换时还要盯恢复这一步。

## 团队如何控制风险

主要动作不是“按一个更大的窗口”，而是把风险拆开：

1. 先在一个机架（一组机器，不是一张卡）上排练两次，跑几十到一百步，做评测、存训练存档，确认没有显存不足或重试。
2. 选一个更稳的并行方式。它比另一种方案略慢，但被丢弃的专家分配更少，也不会让评测后的下一步训练失败。具体配置放在可选技术附录，主线不需要记住。
3. 合并代码、启动子训练，然后在切换后观察一组放行检查；任何一项不过就不算通过。

部署发生在 11-02：合并请求（PR）#10820 在 02:55:41Z 合并，子训练 03:25Z 启动，03:28Z 从第 372,000 步恢复，03:34Z 跑出第一步。04:03:06Z，六项切换后检查在第 372,102 步全部通过，第一次尝试，没有重试。尾段只剩 18,251 步，试错空间小，所以先排练、再切换、再看检查。

## 六项切换后检查各自防什么

这些检查是在切换后观察的放行条件；它们的值是团队/代理报告的。

| 检查项 | 结果 | 在防什么 |
|---|---|---|
| 交叉熵（CE）最大值 | 1.007 | 切换后预测误差没有突然爆高 |
| loss 差（子训练减父训练） | −0.02009 | 没有触发设定的异常阈值；这不等于“没有跳变”，还要区分评测口径 |
| 中位步时（一半的步快于它） | 16.05 秒 | 变慢在可接受范围 |
| drop 均值 | 4.058e-4（约 3.5e-4–4.1e-4） | 超过专家容量后被丢弃的专家分配没有升高 |
| 峰值 HBM（GPU 显存，单位 GiB） | 127.8 GiB | 显存没有顶到上限 |
| 持续梯度尖峰（梯度范数突然变大） | 没有 | 梯度没有持续失控 |

drop 是超过专家容量后，部分专家分配被丢弃的比例；它不表示整条文本或训练数据被删除。CE 是语言模型常用的 loss 形式，衡量模型给正确的下一个 token 分配的概率高不高；这里看的是它的最大值有没有异常。loss 是模型猜下一个 token 的错误程度，越低说明在这批数据上拟合得越好，但它不等于能力更强。

父训练（旧配置的对照）是：14.38 秒/步、loss 0.9982、drop 1.396e-3、HBM 123.2 GiB。用 16.05 对 14.38 算，吞吐约少 10.4%；按表里的 tok/s（每秒处理的 token 数）算约少 11.0%。对外说“约少 10%”，不要用那个按 16.3 秒/步做的预估，它不是实测。

归因也要分清：六项切换后检查由 Marin 作者方/代理报告，没有独立复核；10-22 的 0.031 是外部观察者的测量，不是官方评测。两者不能混着说。

## 为什么现在还不能证明能力

- 截点前没有 65K 评测结果。首次 65K 评测预计在第 375,000 步（约 11-02T17:20Z），永久训练存档预计在第 378,000 步（约 11-03T07:00Z），都在截点之后；训练预计 11-05T15:00Z 完成。这些都是预计，不是已发生。
- 32K 以上没有长上下文能力基准。一套长上下文能力测试（RULER）的接入问题 #7638 在 10-24 被自动清理机器人关闭；65K 阶段只能靠 loss 判断，训练侧的 loss 仍会评，Paloma 这类留出未训练的 held-out 数据也算在内；但它不是能力基准。
- 评测按训练长度打包。切到 65K 后，Paloma 评测集的总分可能阶跃，eval_regressed（评测回归告警，相对父训练 2%）可能误报。这是测量风险，不是“已经回归”。
- 多长度评测的修法（#10711）已批准，但还没合并、与主分支有冲突，也还没有在 GPU 上排练；ClassicLarry 问过，保留最后一个不满打包块（partial chunk）会不会改变 4K/16K 数据，到截点没有实验。
- 评测显存问题的修法（#10709）也还没合并，仍在等评审：单机架的长文本评测里，每 GPU 会多占约 7.4 GiB，余量约 5.8 GiB，下一步训练分配失败；11 个机架没测。
- 切换后检查只覆盖 103 步，也只有这一条训练的一次切换。它证明的是切换那一刻没有翻车，不是接下来 18,251 步都不会翻车；通过检查只说明“未触发设定的异常阈值”，不说明长上下文能力；合并请求是工程动作，不是能力结果。
- Marin 承诺在训练结束后用 4K 重评所有训练存档；到截点没有公开记录，承诺条件是训练结束，所以现在还不能算逾期。

## 可选技术附录（不放进 5–8 分钟主线）

下面这些是配置细节，主线不需要观众学会，想深挖时再看。

- CP 是上下文并行，把一条长文本切到多张卡上算；EP 是专家并行，把 MoE 的专家分到不同卡上。这次用“上下文不切、专家分 64 路”（CP1×EP64）；另一种对照是“长文本切 4 段、专家分 16 路”（CP4×EP16）。
- 单机架 500 步对照：CP4 是 14.699 秒/步、drop 2.41e-3、127.6 GiB；CP1 是 15.397 秒/步、drop 9.80e-4、128.4 GiB。CP1 慢 4.7%，但 drop 少 2.5 倍，所以这次选 CP1。
- capacity factor 是每个专家允许接收的 token 容量倍数，这次取 1.5；qk_mult 是注意力打分的缩放系数，这次取 1.66。qk_mult 只是本次切换的一个设置，不是说换上下文长度就必须调。
- 两次排练：第一次（C1）从第 360000 步跑 60 步，15.571 秒/步，drop 8.29e-4，做了三次 dropless 评测，没有 OOM（显存不足）；第二次（C2）从第 366000 步跑 100 步，15.518 秒/步，drop 1.00e-3，127.9 GiB，做了两次训练存档保存，最终 4.29 TB 的第 366100 步存档完整；但存档恢复没有测。

## 不能夸大的结论

- 不能说“65K 让模型更强”：截点前没有 65K 能力评测，只有 loss 和检查。
- 不能说“loss 没有跳变”：结果是“未触发设定的异常阈值”，评测口径仍要单独看。
- 不能说“切换后检查通过就等于安全”：只覆盖 103 步和一次切换。
- 不能说“评测修法已经可用”：两个修法都还没合并。
- 不能说“训练结束”：预计 11-05 完成，262K 还没开始。
- 不能把“合并代码”写成“能力突破”。
- 不能把“预计”写成“已经发生”。
