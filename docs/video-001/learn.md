# 从 16K 到 65K：三个问题，一条边界

时间窗：这份材料停在 2026-11-02T05:30Z（UTC）。它是历史回顾，不是实时进展；这个时点之后发生的事，这里不写。

## 一、为什么要把一次能读的长度从 16K 拉到 65K？

模型训练做的事很单调：读一段文本，猜下一个 token。token 是模型把文本切分后处理的小片段，不固定等于一个字或一个词。模型一次能读进多少 token，叫上下文；16K 约 1.6 万个 token，65K 约 6.5 万个，K 大约是一千。上下文越长，能拿来猜的材料越多。

材料多是要付钱的。读得越长，要同时照顾的前后关系越多，显卡内存和机器之间的通信都跟着涨。所以这个模型前面大部分训练用更短的上下文（更早是 4K，后来是 16K），便宜；到最后 4.7% 的数据，才把长度改成 65K，让模型适应更长的输入。长度是分阶段加上去的，不是一上来就拉满。

## 二、怎么判断这次切换没把训练搞坏？

先分清两种检查。

工程检查问的是“训练还活着吗”：预测有没有突然变差、每一步是不是慢得离谱、显卡内存有没有顶满。loss 是预测误差；它突然跳高，通常说明哪里不对。训练存档（checkpoint）是模型参数加上恢复所需的状态，存下来就能从原地接着跑。

切换前，团队在一组机器上做了短程演练，评测和存档保存都跑过；演练中新写下的那个存档没有回读。切换后，正式任务从切换前的存档接着跑。不久，一组事先设好阈值的检查一次通过，没有重试。这些检查只覆盖一次运行里的 103 步。通过的意思是“没碰到异常线”，不是“完全安全”。

## 三、为什么还不能说它更会读长文？

因为上面查的是训练，不是能力。

能力评测问的是另一件事：给模型一篇长文，它能不能找到并用上里面那句话。到目前为止，没有 32K 以上的长上下文能力评测。第一次 65K 评测预计在截止之后，所以到这个时点还没有结果。评测本身也有麻烦：它按训练长度打包文本，分数可能在切换点跳一下，这是测量方式带来的，不等于能力退步。

一个教学用的类比，不是 Marin 的实验。短通知只写“上线时间推迟两周，另行通知”，问它为什么推迟、原定哪一天，它答不出来，纸上没有。长版本前面多一句“因为等待第三方安全审计，原定 10 月 15 日的上线将推迟两周”，原因和日期都在。但模型仍可能漏掉这句，尤其当它落在长文中间、或者混在一堆无关内容里。材料在，不等于会用。能输入 65K，不等于能用 65K。

## 自测五题

1. 16K 和 65K 指的是什么？为什么大部分训练不用 65K？
2. token 和上下文是什么关系？
3. 工程检查在查什么？“通过”说明了什么，又没说明什么？
4. 为什么“能输入 65K”不等于“能用 65K”？
5. 到 2026-11-02T05:30Z 为止，有没有 65K 的能力评测结果？为什么？

<summary>参考答案</summary>

1. 指上下文长度，即一次能读进多少 token。越长越贵，所以只在最后 4.7% 用 65K。
2. token 是模型切分后处理的小片段；上下文是一次能读进多少块。
3. 查训练有没有当场坏掉：预测误差、耗时、显卡内存。通过指没碰到事先设的异常线，不代表长期安全，也不代表能力变强。
4. 模型可能漏掉关键句，尤其在中段或噪声里；容量变大，不等于会用。
5. 没有。没有 32K 以上的长上下文评测，第一次 65K 评测预计在截止之后。
