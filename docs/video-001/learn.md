# 从 16K 到 65K：三个问题，一条边界

时间窗：这份材料停在 2026-11-02T05:30Z（UTC）。它是历史回顾，不是实时进展；这个时点之后发生的事，这里不写。

## 一、为什么要把一次能读的长度从 16K 拉到 65K？

模型训练做的事很单调：读一段文本，猜下一个 token；猜完和真实后文比较，再调整模型参数，反复练习。token 是模型把文本切分后处理的小片段，不固定等于一个字或一个词。一次能读进多少 token，叫上下文；16K 约 1.6 万个 token，65K 约 6.5 万个，K 大约是一千。上下文越长，能拿来猜的材料越多。

读得越长，前后关系越多，显卡内存和机器通信都涨。所以这个模型前面大部分训练用更短上下文（4K→16K），便宜；到本次计划最后 4.7% 才切到 65K，让模型适应更长输入。4.7% 是计划步数比例，不是通用规律。

## 二、怎么判断这次切换没把训练搞坏？

工程检查问的是“训练还活着吗”：预测、速度、显卡内存是否正常。loss 是预测误差；突然跳高通常说明哪里不对。训练存档（checkpoint）是模型参数和恢复所需的状态，能接着跑。

切换前，团队在一组机器上做了短程演练，评测和存档保存都跑过；新写下的存档没有回读。切换后，正式任务从这个存档接着跑；随后，一组事先设好阈值的检查一次通过，没有重试。检查只覆盖一次运行的 103 步。通过的意思是“没碰到异常线”，不是“完全安全”。

## 三、为什么还不能说它更会读长文？

因为上面查的是训练，不是能力。

能力评测问：给长文，模型能不能找到并用上里面那句话。到截点，公开记录没有专门的长文能力测试；下一次常规 65K 评测在截点之后，补预测误差，不等于能力测试。要判断能否找到并用上关键信息，还需专门任务测试；公开记录不能下结论，也没说已安排。常规评测按训练长度打包，分数可能跳；这是测量方式，不等于能力退步。

教学类比，不是 Marin 实验。同一份通知，只看最后一段，只有“上线时间推迟两周，另行通知”；问为什么、原定哪天，仅凭这一段无法确定，纸上没有。往前多看一段，前面写着“因为等待第三方安全审计，原定 10 月 15 日的上线将推迟两周”，原因和日期就在同一份材料里。但模型仍可能漏掉这句，尤其在中段或噪声里；也可能猜或编一个。材料在，不等于会用。能输入 65K，不等于能用 65K。

## 自测五题

1. 16K 和 65K 指的是什么？为什么大部分训练不用 65K？
2. token 和上下文是什么关系？
3. 工程检查在查什么？“通过”说明了什么，又没说明什么？
4. 为什么“能输入 65K”不等于“能用 65K”？
5. 到 2026-11-02T05:30Z 为止，公开记录能回答“模型会不会用长文关键信息”吗？为什么？

<summary>参考答案</summary>

1. 指上下文长度，即一次能读进多少 token。越长越贵，所以只在最后 4.7% 用 65K。
2. token 是模型切分后处理的小片段；上下文是一次能读进多少块。
3. 查训练有没有当场坏掉：预测误差、耗时、显卡内存。通过指没碰到事先设的异常线，不代表长期安全，也不代表能力变强。
4. 模型可能漏掉关键句，尤其在中段或噪声里；容量变大，不等于会用。
5. 公开记录没有专门的长文能力测试结果。下一次常规 65K 评测能补预测误差，但不等于能力测试；能否找到并用上关键信息，还要专门任务测试；公开记录也不能下结论。
